## 2. 加一个概念的标准流程

不许跳步。顺序反了会返工。

**① 诊断** —— 一句话写死学生到底卡在哪。
　❌"学生不理解黎曼和" ✅"学生看不出为什么把矩形加起来会变成一个积分号"

**② 找出看不见的量** —— 每个概念都有一个纸上画不出来的东西,它就是主角。

**③ 选主角对象** —— 一个用户能盯着看、能拖的具体东西。**只能有一个。**两个主角=不知道该看哪。

**④ 写推导链** —— 6–9 步,每步必须能回答"上一步怎么变成这一步"。写不出来就拆。

**⑤ 钉死数字** —— 选定函数与区间,用独立脚本(Python/Node 皆可)把每步该显示的数存档到本文件。
　**本文件第 4 节已经替你做完了这一步。**

**⑥ 实现数学** —— 先 `src/math/` 纯函数 + 测试,`npm test` 绿了才碰界面。

**⑦ 实现场景 + 验收** —— 写 `chain.ts` 与 `XxxScene.tsx` → `npm run shots` → **真的看图** → 修 → 提交。

## 4. 分镜规格(数字均已验证)

### 4.1 Riemann Sum → 定积分

**诊断**:学生看不出"把矩形加起来"和"积分号"是同一件事。他们会算黎曼和,也会算积分,但认为那是两个技能。

**看不见的量**:Δx→0 时,误差**怎么**消失的。

**主角**:那一排矩形。

**钉死的例子**:`f(x) = 4 − x²`(复用 `PARABOLA_DOWN`),区间 `[0, 2]`
精确值 `∫₀²(4−x²)dx = 8 − 8/3 = 16/3 = 5.3333333333`

| n | 左端点 | 右端点 | 中点 | 梯形 |
|---|---|---|---|---|
| 1 | 8.000000 | 0.000000 | 6.000000 | 4.000000 |
| 2 | 7.000000 | 3.000000 | 5.500000 | 5.000000 |
| 4 | 6.250000 | 4.250000 | 5.375000 | 5.250000 |
| 8 | 5.812500 | 4.812500 | 5.343750 | 5.312500 |
| 16 | 5.578125 | 5.078125 | 5.335938 | 5.328125 |
| 32 | 5.457031 | 5.207031 | 5.333984 | 5.332031 |
| 64 | 5.395508 | 5.270508 | 5.333496 | 5.333008 |

**关键性质**(这条链的骨架):f 在 [0,2] 上递减 ⇒ **左端点恒高估、右端点恒低估**,
精确值被上下夹住。且 `左 − 右 = (f(0) − f(2))·Δx = 4·Δx`,n=4 时正好 = 2.000000。
⇒ 夹缝宽度与 Δx 成正比 ⇒ Δx→0 时夹缝→0 ⇒ **中间只可能剩一个数**。
这就是"为什么极限存在"的可视化证明,比"越来越接近"强得多。

**分镜**

| # | 标题 | 屏幕上发生什么 | 相机 | 可拖 | 公式 |
|---|---|---|---|---|---|
| 1 | The area under a curve | 曲线 + 区域淡入。narration 点明:我们想要这块面积,但它不是任何一个我们会算的形状 | front | — | — |
| 2 | Rectangles we can measure | 出现 4 个左端点矩形,每个高 = 左边界的 f 值。强调"矩形面积我们会算" | front | n(1–4) | `A ≈ Σ f(xᵢ)Δx` |
| 3 | Too big | 左端点矩形全部高亮成"溢出"色;显示 6.250000 > 真值 | front | n | 左和 = 6.250000 |
| 4 | Too small | 切换成右端点矩形;显示 4.250000 < 真值 | front | n | 右和 = 4.250000 |
| 5 | **Squeezed** | ⭐ 左右两套矩形**同时**显示,真值夹在中间。标出夹缝 = 2.000000 | front | n | `右 ≤ A ≤ 左`,夹缝 = 2.0000 |
| 6 | The gap is Δx-sized | 拖 n,夹缝按比例缩小。显式给出 `左−右 = 4Δx` | front | n(1–64) | `左 − 右 = (f(0)−f(2))Δx = 4Δx` |
| 7 | Δx → 0 | n 走离散档位 [4,8,16,32,64],夹缝→0 | front | — | 夹缝 → 0,只剩一个数 |
| 8 | That number is the integral | 矩形淡出,区域实心填充;`Σ` 形变成 `∫` | front | — | `lim Σ f(xᵢ)Δx = ∫₀²(4−x²)dx = 16/3` |

**必须新写的数学**:`math/riemann.ts` 已有 `riemannSum`,够用。
新增 `leftRightGap(curve, n, interval)` 返回 `左和 − 右和`,并单测它等于 `(f(a)−f(b))·Δx`(单调函数下)。

**必须新写的场景**:`RiemannBars`(一排矩形,参数:n / rule / 颜色 / 透明度)。放 `src/scene/`,因为导数链不用但以后 FTC 会用。

**验收**:n=4 时屏幕上三个数分别是 6.250000 / 4.250000 / 5.333333;拖 n 到 64,夹缝显示 0.125000。

### 4.2 Secant → Tangent

**诊断**:学生会背"导数是切线斜率",但说不出**两个点怎么变成一个点**而斜率还有意义。

**看不见的量**:割线**趋近**的过程本身。

**主角**:曲线上那个可移动的第二点 Q。

**钉死的例子**:`f(x) = x²`(复用 `PARABOLA_UP`),定点 `a = 1`,`f(1) = 1`,`f'(1) = 2`

**选它的全部理由**:割线斜率有恒等式
```
m(h) = ((1+h)² − 1)/h = (2h + h²)/h = 2 + h        (h ≠ 0)
```
**斜率就是 `2 + h`**。屏幕上拖 h,数字里的 "+h" 肉眼可见地缩小 —— 极限过程不再抽象。

| h | 割线斜率 |
|---|---|
| 1 | 3.000000 |
| 0.5 | 2.500000 |
| 0.25 | 2.250000 |
| 0.1 | 2.100000 |
| 0.01 | 2.010000 |
| 0.001 | 2.001000 |
| −0.1 | 1.900000 |

**分镜**

| # | 标题 | 屏幕上发生什么 | 可拖 | 公式 |
|---|---|---|---|---|
| 1 | Two points | 曲线 + P(1,1) 与 Q(1+h, (1+h)²),h=1 | h | — |
| 2 | The line through them | 画割线,标 Δy / Δx 的直角三角形 | h | `m = Δy/Δx = 3.000000` |
| 3 | Slide Q closer | 拖 h:1 → 0.5 → 0.25,割线跟着转 | h | `m = 2.500000 …` |
| 4 | **The slope is literally 2 + h** | ⭐ 代数展开逐项出现,消去 h,留下 `2 + h`。此后拖 h 时公式与数字同步 | h | `m(h) = (2h+h²)/h = 2 + h` |
| 5 | From both sides | h 取负,Q 移到 P 左边;两侧都趋向 2 | h(−1…1, 跳过 0) | 左 1.900000 / 右 2.100000 |
| 6 | h → 0 | h 走离散档位 [0.5, 0.25, 0.1, 0.01],割线肉眼变成切线 | — | `m → 2` |
| 7 | The tangent | 割线换成切线(颜色变,narration 说明它是极限而非"很近的割线") | — | `f'(1) = 2` |
| 8 | Everywhere | 切点沿曲线滑动,显示 `f'(x) = 2x` | x₀ | `f'(x) = 2x` |

**必须新写的数学**:`math/derivative.ts` — `secantSlope(curve, a, h)`、`tangentLine(curve, a)`。
单测:`secantSlope(PARABOLA_UP, 1, h)` 对上表逐项吻合;`h→0` 时与 `curve.df(1)` 一致;`h=0` 必须**抛错**而不是返回 NaN。

**⚠️ 陷阱**:h 滑块必须**跳过 0**(step 不要让它正好落在 0)。允许 h=0 会得到 0/0。
在 `ControlSpec` 层面做不到就在场景里 clamp,并在测试里断言 `secantSlope(..., 0)` 抛错。

**验收**:h=0.25 时屏幕显示 2.250000;h=−0.1 时显示 1.900000;第 4 步之后拖 h,公式里的 `2 + h` 与右边的数字始终一致。

### 4.3 左右极限

**诊断**:学生以为"极限 = 代进去算"。遇到函数在该点无定义就卡住。

**看不见的量**:两侧**分别**逼近,以及"函数在这一点的值"与"极限"是两件事。

**主角**:x 轴上从两侧移向 a 的那个点。

**钉死的例子**:`g(x) = (x²−1)/(x−1)`,`x → 1`
代数上 `g(x) = x + 1`(x ≠ 1),`x = 1` 处**无定义** —— 图像上是 (1,2) 处的一个空心洞。极限 = 2。

| 距离 d | 左 (x=1−d) | 右 (x=1+d) |
|---|---|---|
| 0.5 | 1.500000 | 2.500000 |
| 0.1 | 1.900000 | 2.100000 |
| 0.01 | 1.990000 | 2.010000 |
| 0.001 | 1.999000 | 2.001000 |

**对照组**(第 6–7 步用):`h(x) = x/|x|`,`x → 0`,左 = −1,右 = +1,**极限不存在**。

**分镜**

| # | 标题 | 内容 | 公式 |
|---|---|---|---|
| 1 | A hole in the graph | 画 g,(1,2) 处一个明显的空心圈。narration:这个函数在 x=1 处**没有值** | `g(1)` undefined |
| 2 | Walk in from the left | 点从 x=0.5 向 1 移动,y 值实时显示 | 左 → 1.900000 → 1.990000 |
| 3 | Walk in from the right | 从 x=1.5 向 1 移动 | 右 → 2.100000 → 2.010000 |
| 4 | **They agree** | ⭐ 两侧同时逼近,两个数字向同一个值收拢 | 左 = 右 = 2 |
| 5 | The limit is not the value | 洞还在,但极限存在 = 2。这一步是本链的落点 | `lim = 2`,`g(1)` 仍 undefined |
| 6 | When they disagree | 换成 `x/\|x\|`,两侧分别趋向 −1 和 +1 | 左 = −1,右 = +1 |
| 7 | No limit | 说明极限存在的条件是两侧一致 | `lim` DNE |

**必须新写的数学**:`math/limits.ts` — `approachSequence(f, a, side, steps)` 返回逼近序列;
`oneSidedLimit(f, a, side, tol)`。单测:对 g 两侧都收敛到 2;对 `x/|x|` 两侧不一致。
⚠️ g 在 x=1 处必须**真的**不计算(会得到 0/0),不要偷偷用化简后的 x+1 —— 那就把要讲的东西讲没了。

**验收**:x=0.99 显示 1.990000;x=1 处曲线上有可见的空心洞;第 6 步两侧数字明显不同。

### 4.4 单位圆 → sin/cos

**诊断**:学生把 sin 当"三角形对边比斜边",于是无法理解它为什么会是一个**波**。

**看不见的量**:圆上的点与波形之间的**同步性**。

**主角**:圆上那个转动的点 P。

**钉死的例子**:单位圆 `P(θ) = (cos θ, sin θ)`

| θ | cos θ | sin θ |
|---|---|---|
| 0 | +1.000000 | 0.000000 |
| π/6 | +0.866025 | +0.500000 |
| π/4 | +0.707107 | +0.707107 |
| π/3 | +0.500000 | +0.866025 |
| π/2 | 0.000000 | +1.000000 |
| π | −1.000000 | 0.000000 |
| 3π/2 | 0.000000 | −1.000000 |

弧度的定义要在链里显式出现:**θ = 走过的弧长**(单位圆上)。θ=π/3 时弧长 = 1.047198。

**分镜**

| # | 标题 | 内容 |
|---|---|---|
| 1 | A point on a circle | 单位圆 + 点 P 在 (1,0)。半径线可见 |
| 2 | θ is arc length | 转动 P,高亮走过的弧;标出弧长数值 = θ。**这一步是弧度制的定义** |
| 3 | Drop a vertical line | 从 P 向 x 轴引垂线,标出竖直坐标 = sin θ |
| 4 | **Carry it sideways** | ⭐ 在圆右边放一条时间轴,把 sin θ 的高度**平移**过去描点 |
| 5 | Trace it | θ 从 0 转到 2π,右边描出完整正弦波。圆与波**同一个点在动** |
| 6 | The other coordinate | 换成水平坐标 → 余弦波。指出它只是同一个波平移了 π/2 |
| 7 | Why it repeats | 转第二圈,波形完全重合 → 周期 2π 就是"绕回原处" |

**必须新写的数学**:`math/trig.ts` — `circlePoint(θ)`、`arcLength(θ, r=1)`。
单测:上表逐项;`sin²+cos²=1` 在密集采样上成立;`arcLength(θ,1) === θ`。

**必须新写的场景**:`TracedWave`(把一个随参数变化的标量描成随时间的曲线)。
放 `src/scene/`,以后参数方程、周期运动都会复用。

**验收**:θ=π/6 时读数 0.500000;转满 2π 后波形与标准 sin 图重合;第 5 步圆上的点与波上的点始终水平对齐。

## 5. v2 规格:开放任意函数输入

> **已下线(未删除)。** 主线 UI 入口由 `src/config.ts` 的 feature flag 关闭;
> `src/math/expression.ts`、动态链生成逻辑与全部测试继续保留。后续独立项目见 `docs/ROADMAP.md` W1。

**只有在 4 条链全部完成后才开始。**

### 目标
把 `CurveSpec` 的来源从"精选常量"扩展为"用户输入的表达式",**上层一行不改**。
这个扩展点在 v1 就留好了:所有场景与链只依赖 `CurveSpec` 接口,不依赖具体是哪条曲线。

### 技术选型
- 解析:`mathjs`(`math.parse` + `math.compile`)。**不要自己写解析器。**
- 导数:`math.derivative()` 可给出解析导数,直接产出 `df`。
- 原函数:mathjs **不做符号积分**。所以 `F` / `xF` / `sqF` 三个字段对用户函数**无法给出闭式**。
  ⇒ 必须把 `CurveSpec` 里这三个字段改成**可选**,并让 `solids.ts` / `riemann.ts` 在缺失时
  自动退回 `adaptiveSimpson`。这是 v2 唯一需要动到既有 math 层的地方,**动之前先把全部单测跑绿**。

### 必须处理的边界(每一条都要有测试)
1. 表达式解析失败 → 显示友好错误,**不允许把 NaN 灌进场景**
2. 定义域外(如 `√x` 在 x<0、`1/x` 在 0)→ 采样时跳过并断开曲线,不要画出一条穿越屏幕的直线
3. 函数在区间内取负值 → 旋转体体积公式仍成立但**几何意义变了**,要么禁止要么显式说明
4. 区间端点让积分发散(如 `1/x` 在 [0,1])→ 检测并拒绝,给出人话解释
5. 用户输入的区间 `a ≥ b` → 拒绝
6. 极端取值导致相机装不下 → 根据 f 的值域自动调 `CAMERA_PRESETS` 的距离,或对可视化范围做 clamp
7. 输入框每敲一个字符都重编译 → 必须防抖,否则每帧重建几何体会卡死

### 分期
- **v2.0**:输入框 + 解析 + 区间输入,只接到 **Riemann** 这一条链(2D,风险最低)
- **v2.1**:接到 Shell / Disk(3D,要处理值域与相机自适应)
- **v2.2**:预设下拉 + "试试这个"示例列表(降低空白输入框的门槛)

**先不要做**:隐函数、参数方程、分段函数、极坐标。

## 8. 给接手代理的最后一句

这个项目里最容易被破坏的不是代码,是**两条纪律**:

1. **`src/engine/` 不许为了某个概念改一行。** 它已经扛住了第二个概念,说明抽象是对的。
   第三、第四个概念如果逼你改引擎,先怀疑你的 chain 数据设计,而不是引擎。
2. **数字必须两条独立路径互证。** 这个项目的全部价值建立在"屏幕上的每个数都是对的"之上。
   一个看起来很漂亮但数学错了的动画,是负价值 —— 它会让学生记住错的东西。

其余都可以商量。
